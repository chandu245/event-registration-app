🚀 Built a DevOps learning project that covers the concepts most asked in interviews🚀 
 
If you're preparing for DevOps interviews, you'll know these questions come up constantly:
 
❓ How do you manage secrets in Kubernetes? 
❓ What is IRSA and why is it better than node-level IAM? 
❓ How does Terraform manage state in a team environment? 
❓ What is the difference between a Deployment and a StatefulSet? 
❓ How do you ensure a pod is healthy before traffic hits it? 
❓ How do you structure a CI/CD pipeline for a containerised app?
❓ How do you scan for vulnerabilities before deploying to production?

What the project covers:
 
Kubernetes (EKS) → Deployment vs StatefulSet (Tomcat vs MySQL — and why) → Readiness and liveness probes → envFrom with Kubernetes Secrets → Headless services, LoadBalancer services → EBS persistent volumes with gp3 StorageClass
 
Secrets Management → AWS Secrets Manager as the single source of truth → External Secrets Operator — automatic sync from AWS into K8s → Passwords auto-generated by Terraform, never set by a human → Zero credentials in the pipeline or codebase
 
IAM & Security → IRSA (IAM Roles for Service Accounts) via OIDC federation → Scoped permissions — only the ESO pod can read secrets → EC2 instance role for Jenkins — no access keys anywhere
 
Security Scanning with Trivy → IaC scanning — Terraform configs and Kubernetes manifests checked for misconfigurations on every run → Image scanning — Docker image scanned for known CVEs before it is pushed to ECR → Pipeline fails automatically if a CRITICAL vulnerability is found → .trivyignore for managing accepted false positives
 
Terraform → S3 remote state with DynamoDB locking → Modular structure — VPC, EKS, ECR, Secrets Manager in separate files → random_password for automated secret lifecycle → Bootstrap pattern for state backend
 
CI/CD with Jenkins → Pipeline as code (Jenkinsfile) → Parameterised pipeline — Deploy and Destroy with one click → Fully automated — push code, pipeline handles the rest → checkout scm — works with any fork, no hardcoded URLs
 
Docker → Multi-stage build — Maven build stage + Tomcat runtime stage → Image pushed to AWS ECR only after Trivy scan passes → No secrets baked into the image
 
Honest disclaimer: This is a learning project, not a production deployment. It uses a single node, public subnets, and MySQL inside the cluster instead of RDS. The goal is to understand the patterns — not to run real workloads on it.
 
Who this is for: → You know some AWS but haven't tied it all together → You're preparing for DevOps or Cloud interviews → You want a real project beyond "deploy to EC2 with a bash script"
